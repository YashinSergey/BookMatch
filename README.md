# BookMatch

Учебный проект рекомендаций книг на Goodbooks-10k: Popularity, Content-Based, Item-Based CF и SVD.

## Результаты и выводы

После очистки осталось 978 845 оценок, 53 417 пользователей и 10 000 книг. Проверены 12 конфигураций моделей. Параметры выбраны по nDCG@10 на validation.

Итоговые результаты на test:

| Модель | Precision@10 | Recall@10 | nDCG@10 | RMSE |
|---|---:|---:|---:|---:|
| Popularity | 0,00015 | 0,00152 | 0,00076 | 0,9441 |
| Content-Based | 0,01727 | 0,17271 | 0,10434 | — |
| Item-Based CF | 0,02527 | 0,25270 | 0,16601 | 0,9733 |
| SVD | 0,00013 | 0,00132 | 0,00061 | 0,8679 |

Релевантными считаются книги с оценкой ≥4. Рекомендации оцениваются по 30 190 пользователям с релевантной тестовой книгой, RMSE - по всем 45 054 тестовым оценкам. Кандидаты — весь каталог, кроме книг из обучающей истории. У каждого оцениваемого пользователя одна релевантная книга, поэтому Recall@10 равен доле попаданий в Top-10, а максимальный Precision@10 — 0,1. Content-Based не предсказывает оценки, поэтому RMSE для него не рассчитывается.

- **Item-Based CF лучше всего решает задачу Top-N:** доля попаданий — 25,3%. Метод использует связи с книгами, которые понравились пользователю.
- **Content-Based уступает ItemCF:** доля попаданий — 17,3%. Названия и теги описывают содержание, но не полностью отражают предпочтения читателя. История оценок книги не требуется.
- **SVD лучше предсказывает оценки**, но плохо ранжирует каталог. Он обучается восстанавливать оценки, а не порядок рекомендаций. Низкий RMSE не гарантирует высокого nDCG.
- **Popularity даёт слабый результат.** Высокая средняя оценка книги не учитывает интересы конкретного пользователя.

Для этого прототипа основным методом рекомендаций выбран бы ItemCF. Для новых книг можно добавить контентный подход. Такой гибрид пока не реализован. Основные проблемы данных - разреженность около 99,82%, короткие истории и отсутствие дат событий. Оценка выполнена на случайном разбиении и не показывает качество рекомендаций во времени.

Полные метрики: [reports/test.csv](reports/test.csv). Результаты подбора: [reports/validation.csv](reports/validation.csv).

## Установка

Проверено на Python 3.13.1. Из корня проекта:

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyterlab
```

В `data/archive/` нужны `books.csv`, `ratings.csv`, `tags.csv`, `book_tags.csv` из [датасета Goodbooks-10k](https://www.kaggle.com/datasets/zygmunt/goodbooks-10k). Использована версия с 981 756 оценками и колонками `id` / `book_id` в каталоге. Более новая версия GitHub имеет отличия.

## Работа с проектом

1. `Notebooks/EDA.ipynb` — анализ и очистка данных.
2. `Notebooks/Models.ipynb` — обучение, подбор параметров, метрики, примеры и выводы. Выполните все ячейки сверху вниз.

Модели остаются в памяти ноутбука. После перезапуска ядра их нужно обучить заново.

Можно запустить обучение без ноутбука:

```bash
python -m src.experiment
```

Параметры находятся в `experiments.json`. Результаты сохраняются в `reports/validation.csv` и `reports/test.csv`. Метрика подбора — nDCG@10. Test используется после выбора параметров.

## Код

- `src/data.py` — загрузка, очистка, разбиение и матрица взаимодействий
- `src/popularity.py`, `content.py`, `item_cf.py`, `svd.py` — классы моделей
- `src/base.py` — выбор рекомендаций и исключение прочитанных книг
- `src/metrics.py` — Precision@K, Recall@K, nDCG@K и RMSE
- `src/experiment.py` — обучение и сравнение

Методы `get_recommendations(user_id, N=5)` и `get_similar_books(book_id, N=5)` показаны в итоговом ноутбуке. Они возвращают локальные ID книг — исходную колонку `books.id`.

Описание оценки, сравнение моделей, вычислительная сложность и предложенная стратегия гибридизации находятся в `Models.ipynb`.
